# Adrobot · редактор кампаний Keitaro

FastAPI, SQLAlchemy, Alembic, SQLite и HTML/JavaScript. Приложение создаёт кампании через Keitaro Admin API и сохраняет черновики, архив офферов и закреплённые доли локально.

## Запуск

Требуется Python 3.10+. Создайте окружение и установите зависимости.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Если файла `.env` ещё нет, создайте его на основе `.env.example`. Укажите адрес тестового Keitaro в `KEITARO_URL` и ключ Admin API в `KEITARO_API_KEY`. По умолчанию используется SQLite в файле `adrobot.db`.

Создатель кампаний ищет в Keitaro существующий домен `https://in.posdk.xyz/`, группу кампаний `FORTESTS` и источник трафика `FORTESTS`. Их можно переопределить в `.env` через `KEITARO_CAMPAIGN_DOMAIN`, `KEITARO_CAMPAIGN_GROUP` и `KEITARO_CAMPAIGN_SOURCE`.

```bash
alembic upgrade head
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте http://localhost:8000. Главная страница перенаправляет на вкладку [Создаватор](http://localhost:8000/creator). Вкладка [Редактор](http://localhost:8000/editor) работает на том же сервере. После создания нажмите «Редактировать» напротив новой кампании, чтобы сразу загрузить её потоки. Схема приложения доступна по адресу http://127.0.0.1:8000/docs. Запускайте приложение с одним воркером. Редактор рассчитан на локальное использование, с общим черновиком на поток.

Если основной домен отсутствует, приложение выбирает первый активный домен в порядке ответа Keitaro с положительным статусом проверки и без указанной ошибки настройки. Если подходящих доменов нет, создание останавливается.

Для запуска автоматических проверок выполните `python -m unittest discover -s tests`. Тесты используют временную БД и подменённый API Keitaro. Файл `.env` и доступ к трекеру для них не требуются.

## Сценарий проверки

1. Введите название кампании и двухбуквенные коды стран через запятую, например `MX,AU,RO`. Найдите оффер по названию, выберите его из подсказок и нажмите «Создать». Первый поток отправляет посетителей из указанных стран в Google, второй отправляет остальных на выбранный оффер.
2. Введите ID кампании или начните вводить название и выберите подсказку (до 20 совпадений). Для поиска сервер хранит каталог кампаний в памяти 60 секунд. Затем нажмите **Fetch Streams**. После загрузки потоков появится каталог офферов. В потоке с офферами начните вводить название или ID, выберите оффер из подсказок и нажмите «Добавить». Проверьте перераспределение. **Отмена** возвращает последнее загруженное или опубликованное состояние.
3. Удалите оффер через **Remove** и нажмите **Push**. В редакторе оффер останется в архиве с долей 0%. Нажмите **Bring Back**, затем **Push**, чтобы вернуть его в Keitaro.
4. Удалите оффер в самом Keitaro и повторите **Fetch Streams**. Ранее загруженный оффер появится в архиве. Если поток изменился при открытом черновике, загрузите его заново и сбросьте черновик перед повторным внесением правок.

## Доли и ошибки

Admin API документирует целочисленный `share`. Закреплённые доли сохраняются при перерасчёте, свободный остаток делится поровну с точностью до процентного пункта. Остаток округления получают офферы с меньшими ID. Например, при закреплённых 25% два остальных оффера получают 38% и 37%. Активные доли после правки дают ровно 100%. Удаление последнего активного оффера и распределения, при которых хотя бы одному активному офферу не хватает 1%, отклоняются.

Кампания создаётся выключенной. Adrobot отправляет команду включения после создания обоих потоков. Если настройка прервалась, сообщение содержит полученный ID кампании. При тайм-ауте во время включения результат команды может быть неизвестен. Откройте кампанию по ID в Keitaro и проверьте её состояние перед повтором.

## Состояние редактора и границы проверки

Одна запись SQLAlchemy соответствует потоку. В JSON хранятся опубликованный состав, черновик, закрепления и ID архивных связей. Единица публикации и отмены — весь состав потока, поэтому снимки сохраняются в одной транзакции. Архива достаточно для Bring Back; отдельного журнала действий пользователей в приложении нет.

Каталог отражает офферы, доступные пользователю Admin API. Единственный результат возможен при ограниченных правах. Сценарии с несколькими офферами, ошибками сети и частичным созданием проверяются на подменённом API. Тесты подтверждают отправляемые запросы; для подтверждения реальной маршрутизации и публикации нужен отдельный разрешённый прогон на тестовом трекере.
